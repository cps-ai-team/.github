## Start here — new starters

> **This section is a starting template and will be revised.**  
> On your first day, follow the steps below as a rough guide. Ask your manager or a colleague if anything is unclear or out of date.

### Day 1 checklist *(template — edit to reflect current process)*

- [ ] Get access to this GitHub organisation (ask your manager)
- [ ] Install Git, .NET SDK and PAC CLI — see [useful-resources](https://github.com/cps-ai-team/useful-resources) for setup guides
- [ ] Review the CPS delivery standards in [sop-library](https://github.com/cps-ai-team/sop-library)
- [ ] Browse two or three delivered solutions in [solution-catalogue](https://github.com/cps-ai-team/solution-catalogue) to see what "done" looks like
- [ ] Introduce yourself to the team and ask who is leading your first engagement

### Days 2–3 *(template)*

- [ ] Complete a Copilot Studio learning path — links in [useful-resources](https://github.com/cps-ai-team/useful-resources)
- [ ] Try the [use-case-matrix](https://github.com/cps-ai-team/use-case-matrix) with sample data to understand how we prioritise AI opportunities
- [ ] Read the core agent-design patterns in [pnp-library](https://github.com/cps-ai-team/pnp-library)

### Days 4–5 *(template)*

- [ ] Familiarise yourself with the **Art of the Possible** and **Agent in a Day** packs in [asset-library](https://github.com/cps-ai-team/asset-library)
- [ ] Make your first contribution: raise a PR to fix a typo, add a useful link, or improve a README

## Not sure where something belongs?

Use this quick decision test:

| The content is… | It belongs in… |
|---|---|
| A mandatory process or control | `sop-library` |
| Reusable guidance explaining a solution approach | `pnp-library` |
| A copy-and-adapt file used in a customer engagement | `asset-library` |
| A learning link, external doc, or tool-install guide | `useful-resources` |
| Evidence of a delivered solution | `solution-catalogue` or the project repo |

## Contribution and ownership

- **Every library has an owner** responsible for reviewing content on a regular cadence. See the `README.md` in each repository for the current owner and review schedule.
- **Changes are made through pull requests.** Open a PR against the relevant library, describe what you are adding or changing and why, and request a review from the library owner.
- **Keep libraries focused.** If you are unsure whether content fits, check the *"What belongs here"* section in the library README or ask the owner before raising a PR.
- **Templates in this repository** (`templates/knowledge-library/`) provide the standard structure for creating a new information library. Copy them when spinning up a new repository.
